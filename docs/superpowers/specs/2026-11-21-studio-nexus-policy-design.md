# Studio Nexus 采集、训练与推理

首个工作区使用带实体主臂输入的 Nexus SO-101 桌面和本机 LeRobot ACT。用户在 Makepad 中配置输入与执行主机、看相机和仿真关节、重置并录制、审阅并选择数据、训练并选择检查点、运行并回看推理。工具链的完成状态与抓放结果单独显示。

依据 Nano v0.4 ST-01、ST-03、ST-13 至 ST-17、ST-21、ST-23 和 [Studio 原生插件契约](../../PLUGINS.md)。

## 界面与归属

- 控制插件提供 SO-101 Nexus 设置和运行入口。绑定本机 Python、主臂串口、保存的标定与运行目录。
- 采集插件的录制工作区展示正视相机、三维模型、关节目标与读回和明确的后端确认。重置确认并稳定后才可开始。结束进入待审阅，再保存为 LeRobot v3 或丢弃。
- 数据工作区复用数据集与回看。所选数据集可进入训练，排除列表和选择的片段写入任务来源。
- 新增一个 `dorobot.policy` 插件。训练页选择数据与步数，显示本机 ACT 的状态、真实进度、损失和有效检查点。推理页选择检查点并用同一 Nexus 场景运行，显示相机、关节与运行和任务结果，并保留视频。
- 保持 Nano 与现有真机工作流。首个集成在 Linux 上运行。后端报告能力和错误，后续可接 Mac 与云端执行后端。

## 运行边界

共享 Rust 后端负责作业生命周期、可用操作、数据选择、相机预览和路径。独立 Rust Nexus 子进程运行物理，LeRobot 工作进程管理主臂读取、LeRobot v3 写入、ACT 和检查点推理。每个 Studio 工作区最多一个本地作业。切换面板不会停止作业。采集和推理使用同一场景、六关节和正视相机，操作均在 Studio 内完成。

## 首期验收

同一构建中验证由实际按钮驱动的 Nexus 会话、重置确认、录制、审阅保存、LeRobot v3 真实性、数据排除、ACT 检查点、闭环推理以及结果视频和状态。可用录制的主臂输入或仿真输入做自动化验证，物理主臂测试按操作者准备情况单独记录。抓放成功、实时帧率和物理回放复现分别测量。
