# Rust 插件工作台验证计划

目标：在 `feat/rust-plugin-workbench` 分支把现有采集和控制界面拆成独立 Rust crate，通过统一 SDK 注册、创建和驱动，并保持原有数据与硬件行为。

架构：共享库提供后端与通用控件；SDK 提供插件描述、面板工厂、上下文和生命周期；宿主只负责组合、挂载、导航和事件分发。本轮使用编译时链接，插件与宿主使用同一 Makepad 版本；动态库安装、Zenoh 和远程机器人接入另行实现。

技术：Rust 2021、固定 Makepad、Cargo 工作区；沿用现有 Rust 原生运行时。

## 文件边界

- `crates/dorobot-studio-core/`：从原应用分离的共享实现，保留后端与回放。
- `crates/dorobot-studio-plugin/`：SDK、注册表、面板生命周期及测试。
- `plugins/collection/`：采集界面与界面事件到业务意图的映射。
- `plugins/control/`：设置／控制界面与事件映射。
- `dorobot-flex/`：组合入口、兼容导出和插件工具箱。
- `docs/PLUGINS.md`：贡献接口、运行和验证方法、当前限制。

## 全局约束

- 新增插件和宿主代码全部使用 Rust；不新增 Python、JavaScript 或 TypeScript 实现。
- 保留默认启动命令、视频特性、中英文、现有数据格式和硬件保护逻辑。
- 插件注册和界面构造不连接真实硬件；数据／硬件操作仍通过现有 Backend 服务。
- 无业务理由不更改第三方代码和原生运行时。

## 检查重点

- 重复插件／面板 ID、未知类型不能覆盖已注册内容。
- 同一个插件工厂能创建互相独立的面板实例。
- 待保存片段或运行中控制不能被插件禁用操作破坏。
- 原有工作流、状态恢复和资源根路径在拆分后保持有效。
- 插件界面通过工厂挂载，实际按钮事件仍抵达生产后端。
